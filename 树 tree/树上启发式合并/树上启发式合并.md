树上启发式合并（**DSU on Tree / Sack**）是一种非常经典的树上离线统计技巧。

它最适合解决这样一类问题：

> 对树上的每个节点 (u)，都要求某个关于“(u) 的整棵子树”的统计信息，例如：
>
> * 子树中不同颜色的数量
> * 子树中出现次数最多的颜色
> * 子树中某个值出现了多少次
> * 子树中满足某种性质的节点个数
>
> 同时，我们能够做到：
>
> * 加入一个节点的信息
> * 删除一个节点的信息
> * 根据当前所有节点的信息快速得到答案

它的核心思想可以概括成一句话：

> **每次计算一个节点的子树答案时，保留它的“重儿子”统计结果，只把轻儿子的贡献加入进去，从而避免大量重复计算。**

下面从普通暴力开始，一步一步推导为什么需要 DSU on Tree，以及它到底是怎么做到 (O(n\log n)) 的。

---

# 1. 先看最直接的问题

假设有一棵根为 (1) 的树，每个节点有一个颜色：

```text
        1
      /   \
     2     3
    / \     \
   4   5     6
```

颜色：

```text
1: red
2: blue
3: red
4: blue
5: red
6: green
```

现在要求：

> 对每个节点 (u)，求 (u) 的子树中不同颜色的数量。

例如：

```text
subtree(1) = {1,2,3,4,5,6}
颜色 = red blue red blue red green
不同颜色 = 3

subtree(2) = {2,4,5}
颜色 = blue blue red
不同颜色 = 2
```

---

# 2. 最简单的暴力

对于每个节点 (u)，直接 DFS 一遍它的子树。

伪代码：

```cpp
for (u = 1; u <= n; u++) {
    dfs(u);
    统计 subtree(u);
}
```

问题来了：

如果树是一条链：

```text
1
|
2
|
3
|
4
|
5
|
...
|
n
```

那么：

```text
subtree(1) 有 n 个节点
subtree(2) 有 n-1 个节点
subtree(3) 有 n-2 个节点
...
```

总复杂度：

[
n+(n-1)+(n-2)+\cdots+1=O(n^2)
]

所以最坏情况下会达到 (O(n^2))。

---

# 3. 能不能复用之前算过的信息？

这是 DSU on Tree 的出发点。

假设我们已经计算完：

```text
subtree(4)
```

现在计算：

```text
subtree(2)
```

显然：

[
subtree(2)={2}\cup subtree(4)\cup subtree(5)
]

那么我们已经知道 `subtree(4)` 的信息，就没必要再从头计算。

但是问题是：

> 到底应该保留哪个儿子的答案？

这就是“**重儿子**”出现的原因。

---

# 4. 什么是重儿子？

对于一个节点 (u)，定义：

[
size[u]=u\text{ 的子树大小}
]

在所有儿子中，子树最大的那个叫做：

> **重儿子（Heavy Son）**

其他儿子叫：

> **轻儿子（Light Son）**

例如：

```text
        1
      / | \
     2  3  4
    / \
   5   6
```

假设：

```text
size[2] = 3
size[3] = 1
size[4] = 1
```

那么：

```text
son[1] = 2
```

因为节点 2 的子树最大。

---

# 5. DSU on Tree 最核心的思想

考虑计算节点 (u)。

假设：

```text
        u
      / | \
     a  b  c
```

并且：

```text
a = 重儿子
b,c = 轻儿子
```

我们采用这样的顺序：

```text
1. 先计算所有轻儿子
2. 清除轻儿子的统计信息
3. 计算重儿子
4. 保留重儿子的统计信息
5. 把所有轻儿子的节点重新加入
6. 加入 u 自己
7. 此时统计结构恰好就是 subtree(u)
```

这里最关键的是：

> **重儿子的统计结果不删除，轻儿子的统计结果删除后再重新加入。**

这就是所谓的“启发式合并”。

---

# 6. 为什么要保留重儿子？

假设：

```text
           1
        /     \
       2       3
      /|\
     4 5 6
```

其中节点 2 是重儿子。

计算 1 时：

先处理轻儿子：

```text
3
```

处理完以后把它清掉。

然后处理重儿子：

```text
2
```

计算完以后保留。

现在当前统计结构中：

```text
只有 subtree(2)
```

然后把：

```text
subtree(3)
```

全部加入。

最后加入节点 1。

就得到：

```text
subtree(1)
```

---

# 7. 为什么这样不会退化成 (O(n^2))？

这是 DSU on Tree 最重要的地方。

关键性质：

> **一个节点只有在它属于某个节点的轻子树时，才会被重新加入。**

而一个节点不可能很多次成为“轻儿子”。

---

# 8. 轻边最多经过 (O(\log n)) 次

假设：

```text
u -> v
```

是一条轻边。

因为 (v) 是轻儿子，所以：

[
size[v]\le \frac{size[u]-1}{2}
]

也就是说，进入轻儿子后，子树大小至少缩小一半。

例如：

```text
n
↓
n/2
↓
n/4
↓
n/8
↓
...
```

最多经过：

[
O(\log n)
]

次。

所以任何一个节点最多被重复加入 (O(\log n)) 次。

因此：

[
O(n\log n)
]

这就是 DSU on Tree 的复杂度来源。

---

# 9. 一个非常重要的直觉

可以把它理解为：

> **大块数据尽量保留，小块数据不断搬运。**

例如：

```text
大块：100000 个节点
小块：10 个节点
```

我们当然希望：

```text
保留 100000
然后把 10 个加入进去
```

而不是：

```text
删除 100000
再重新加入 100000
```

所以：

> **重儿子 = 最大的数据块**
>
> **轻儿子 = 小数据块**

DSU on Tree 本质上就是：

> **让大块留下来，小块往大块里面合并。**

---

# 10. DSU on Tree 和普通 DSU 有什么关系？

虽然名字叫：

> DSU on Tree

但它实际上和传统的：

```cpp
Disjoint Set Union
```

也就是并查集，没有直接关系。

这里的 DSU 更多是指：

> **利用“按大小合并”的思想减少重复工作。**

所以不要把它理解成：

```text
树上跑并查集
```

更准确的理解应该是：

> **树上的启发式合并统计。**

---

# 11. 标准 DSU on Tree 的框架

一般要先做第一遍 DFS，求：

```cpp
size[u]    // 子树大小
son[u]     // 重儿子
```

例如：

```cpp
void dfs1(int u, int fa) {
    sz[u] = 1;

    for (int v : g[u]) {
        if (v == fa) continue;

        dfs1(v, u);

        sz[u] += sz[v];

        if (sz[v] > sz[son[u]]) {
            son[u] = v;
        }
    }
}
```

注意：

```cpp
son[u]
```

记录的是子树最大的儿子。

---

# 12. 为什么通常还要求 dfn / tin / tout？

这是 DSU on Tree 实现中非常关键的一点。

我们通常会给树进行 DFS 序。

例如：

```text
        1
      /   \
     2     3
    / \     \
   4   5     6
```

DFS 序可能是：

```text
1 2 4 5 3 6
```

于是每一个子树对应 DFS 序上的连续区间：

```text
subtree(u)
=
[tin[u], tout[u]]
```

例如：

```text
subtree(2) = [2,4]
```

因为：

```text
2 4 5
```

恰好连续出现。

这样我们就可以：

> **整段扫描一个子树，而不需要递归访问树结构。**

例如：

```cpp
for (int i = tin[u]; i <= tout[u]; i++) {
    int x = rev[i];
    add(x);
}
```

# 13. 经典 DSU on Tree 的 `dfs`

最经典的写法大概是：

```cpp
void dfs(int u, int fa, bool keep) {
    // 1. 处理所有轻儿子
    for (int v : g[u]) {
        if (v == fa || v == son[u]) continue;
        dfs(v, u, false);
    }

    // 2. 处理重儿子
    if (son[u]) {
        dfs(son[u], u, true);
    }

    // 3. 把所有轻子树加入
    for (int v : g[u]) {
        if (v == fa || v == son[u]) continue;
        add_subtree(v, u);
    }

    // 4. 加入自己
    add(u);

    // 5. 当前统计结构就是 subtree(u)
    ans[u] = get_answer();

    // 6. 如果不保留，就全部清除
    if (!keep) {
        clear_subtree(u);
    }
}
```

这是最重要的模板。

---

# 14. `keep` 是什么？

你会经常看到：

```cpp
dfs(u, fa, true);
dfs(u, fa, false);
```

这个参数表示：

> 当前节点处理完以后，要不要保留当前统计信息。

---

## `keep = true`

表示：

> **保留当前子树的信息**

典型情况：

```cpp
dfs(son[u], u, true);
```

因为重儿子要留下。

---

## `keep = false`

表示：

> 当前子树计算完成后，不需要继续使用，所以清空。

轻儿子一般这样：

```cpp
dfs(v, u, false);
```

这样算完之后，它的信息就被清掉了。

---

# 15. 为什么轻儿子要 `false`？

假设：

```text
u
├── heavy
├── light1
├── light2
└── light3
```

如果我们处理：

```text
light1
```

算完之后把它留着。

然后处理：

```text
light2
```

那么统计结构就会变成：

```text
light1 + light2
```

继续处理 `light3`：

```text
light1 + light2 + light3
```

这会导致状态不断叠加，很难保证下一次计算状态正确。

所以：

```text
轻儿子算完
↓
立即清空
```

然后：

```text
重儿子算完
↓
保留
```

最后：

```text
重儿子 + 所有轻儿子 + u
```

# 16. 用一个完整例子模拟

考虑：

```text
        1
      /   \
     2     3
    / \
   4   5
```

假设：

```text
size[2] = 3
size[3] = 1
```

所以：

```text
son[1] = 2
```

现在执行：

```cpp
dfs(1, 0, ...)
```

---

## 第一步：处理轻儿子 3

```cpp
dfs(3, 1, false);
```

处理完以后：

```text
当前统计 = 空
```

因为 `keep = false`。

---

## 第二步：处理重儿子 2

```cpp
dfs(2, 1, true);
```

处理过程中：

```text

```

最后：

```text
当前统计 = subtree(2)
```

并且保留。

## 第三步：加入轻儿子 3

```cpp

```

于是：

```text

```

## 第四步：加入节点 1

```cpp

```

现在：

```text

```

所以可以直接回答：

```cpp
ans[1] = query();
```

# 17. `add()` 到底是什么？

DSU on Tree 本身并不关心你统计什么。

它只要求你能够实现：

```cpp
add(x);
remove(x);
```

或者：

```cpp
update(x, +1);
update(x, -1);
```

例如我们要求：

> 子树中不同颜色的数量。

那么：

```cpp
cnt[color[x]]++;
```

如果：

```cpp
cnt[color[x]] == 1
```

说明这个颜色第一次出现：

```cpp
distinct++;
```

删除：

```cpp
cnt[color[x]]--;

if (cnt[color[x]] == 0)
    distinct--;
```

于是：

```cpp
add(x)
remove(x)
```

就能维护：

```cpp
distinct
```

---

# 18. 一个完整的“统计不同颜色”模板

例如：

```cpp
#include <bits/stdc++.h>
using namespace std;

const int N = 200005;

vector<int> g[N];

int col[N];
int sz[N];
int son[N];

int cnt[N];
int ans[N];
int distinct = 0;

void dfs1(int u, int fa) {
    sz[u] = 1;

    for (int v : g[u]) {
        if (v == fa) continue;

        dfs1(v, u);

        sz[u] += sz[v];

        if (sz[v] > sz[son[u]]) {
            son[u] = v;
        }
    }
}

void add(int u) {
    int c = col[u];

    cnt[c]++;

    if (cnt[c] == 1) {
        distinct++;
    }
}

void removeNode(int u) {
    int c = col[u];

    cnt[c]--;

    if (cnt[c] == 0) {
        distinct--;
    }
}
```

然后：

```cpp
void addSubtree(int u, int fa) {
    add(u);

    for (int v : g[u]) {
        if (v == fa) continue;
        addSubtree(v, u);
    }
}
```

清除：

```cpp
void clearSubtree(int u, int fa) {
    removeNode(u);

    for (int v : g[u]) {
        if (v == fa) continue;
        clearSubtree(v, u);
    }
}
```

核心 DSU：

```cpp
void dfs2(int u, int fa, bool keep) {

    // 1. 轻儿子
    for (int v : g[u]) {
        if (v == fa || v == son[u]) continue;

        dfs2(v, u, false);
    }

    // 2. 重儿子
    if (son[u]) {
        dfs2(son[u], u, true);
    }

    // 3. 加入所有轻子树
    for (int v : g[u]) {
        if (v == fa || v == son[u]) continue;

        addSubtree(v, u);
    }

    // 4. 加入自己
    add(u);

    // 5. 得到答案
    ans[u] = distinct;

    // 6. 如果不保留，就清空整个子树
    if (!keep) {
        clearSubtree(u, fa);
    }
}
```

最后：

```cpp
dfs1(1, 0);
dfs2(1, 0, true);
```

即可得到每个节点的答案。

---

# 19. 为什么最后 `dfs2(1,0,true)`？

根节点处理完之后，我们其实也可以不清。

因为程序结束了。

所以：

```cpp
dfs2(1, 0, true);
```

或者：

```cpp
dfs2(1, 0, false);
```

对于最终答案通常都没有区别。

常见写法就是：

```cpp
dfs(1, 0, true);
```

---

# 20. DSU on Tree 真正的复杂度

很多初学者看到：

```cpp
addSubtree(v)
```

会产生一个疑问：

> 这不是可能每次都扫整个子树吗？

没错。

但关键是：

> **只有轻子树会被这样重新扫描。**

对于某个节点 (x)，它每次进入“轻边”之后，所在子树大小至少减半。

因此：

[
\text{每个节点最多被重新处理 }O(\log n)\text{ 次}
]

所以如果：

```text
add = O(1)
remove = O(1)
```

那么总体复杂度：

[
O(n\log n)
]

---

# 21. 为什么很多模板甚至可以不用 `remove()`？

有些题可以使用另一种写法：

```cpp
dfs(u, fa, keep)
```

然后用 DFS 序：

```cpp
for (int i = tin[v]; i <= tout[v]; i++)
    add(dfn[i]);
```

清除时：

```cpp
for (int i = tin[u]; i <= tout[u]; i++)
    remove(dfn[i]);
```

这就是比较常见的完整模板。

# 22. 一个更标准的模板

我建议你记住下面这个版本：

```cpp
void dfs1(int u, int fa) {
    sz[u] = 1;

    for (int v : g[u]) {
        if (v == fa) continue;

        dfs1(v, u);

        sz[u] += sz[v];

        if (sz[v] > sz[son[u]]) {
            son[u] = v;
        }
    }
}

void dfs2(int u, int fa, bool keep) {

    // 轻儿子：计算完就清掉
    for (int v : g[u]) {
        if (v == fa || v == son[u]) continue;

        dfs2(v, u, false);
    }

    // 重儿子：保留统计信息
    if (son[u]) {
        dfs2(son[u], u, true);
    }

    // 把轻儿子重新加入
    for (int v : g[u]) {
        if (v == fa || v == son[u]) continue;

        addSubtree(v, u);
    }

    // 加自己
    add(u);

    // 得到答案
    solve(u);

    // 不需要保留
    if (!keep) {
        clearSubtree(u, fa);
    }
}
```

这几行的含义一定要理解：

```cpp
dfs2(light, false);
dfs2(heavy, true);
addSubtree(light);
add(u);
```

基本就是整个 DSU on Tree 的灵魂。

---

# 23. 为什么顺序不能乱？

例如你可能想写：

```cpp
dfs(heavy);
dfs(light);
add(light);
```

这是不对的。

正确顺序是：

```text
轻
↓
重
↓
轻重新加入
↓
自己
```

原因是：

### 轻儿子

算完以后要清。

### 重儿子

算完以后要保留。

### 轻儿子重新加入

此时重儿子的统计已经存在，所以直接把轻儿子的全部信息并进去。

### 加自己

最后才得到整个 `subtree(u)`。

所以：

```text
重 + 轻 + 自己
```

就是最终状态。

---

# 24. 为什么叫“启发式”？

因为我们并不是严格按照某种数学上的最优策略，而是选择：

> **保留最大的那一块。**

也就是：

```cpp
if (sz[v] > sz[son[u]])
    son[u] = v;
```

这实际上就是经典的“按大小合并”思想。

---

# 25. DSU on Tree 和“小树合并”有什么区别？

你可能还会遇到另一个名字：

> 树上启发式合并

有时它指的是：

```text
small-to-large
```

这种做法。

例如：

```cpp
map<int,int>* dfs(u)
```

每个节点维护一个集合：

```text
小集合合并进大集合
```

这和 DSU on Tree 的思想本质上非常接近。

---

## Small-to-large

通常是：

```text
每个子树维护一个 map/set
小的往大的合并
```

复杂度：

[
O(n\log n)
]

甚至根据数据结构不同可能更高。

---

## DSU on Tree

则是：

```text
重儿子保留
轻儿子删除后重新加入
```

它不一定显式维护：

```cpp
set / map
```

而经常是维护：

```cpp
cnt[color]
```

因此速度通常更快。

---

# 26. 两者最重要的区别

可以这样理解：

### Small-to-large

```text
真的有很多个“集合”
然后把小集合并入大集合
```

### DSU on Tree

```text
只有一个“全局统计结构”
不断切换当前维护的子树
```

这是非常重要的区别。

---

# 27. DSU on Tree 能解决什么？

典型问题包括：

### 1. 子树不同颜色数

```text
ans[u] = distinct colors in subtree(u)
```

---

### 2. 子树众数

求：

```text
出现次数最多的颜色
```

可以维护：

```cpp
cnt[color]
```

再维护：

```cpp
mx
```

---

### 3. 出现次数恰好为 k 的颜色数

维护：

```cpp
cnt[color]
```

以及：

```cpp
num[f]
```

表示：

```text
当前有多少颜色出现了 f 次
```

---

### 4. 子树颜色频率统计

例如：

```text
每个节点 u，询问：
颜色 x 在 subtree(u) 中出现多少次
```

---

### 5. 子树中满足某个数论性质的节点数量

只要：

```text
add(x)
remove(x)
```

可以维护，就可以考虑 DSU on Tree。

---

# 28. 什么样的问题不适合 DSU on Tree？

如果你的状态：

```text
加入一个节点
```

不能快速维护，

或者：

```text
删除一个节点
```

非常困难，

那么 DSU on Tree 就不好用了。

例如某些需要复杂整体重构的数据结构。

核心要求其实就是：

> **当前集合可以动态加入 / 删除元素。**

---

# 29. 一个很重要的抽象

你完全可以把 DSU on Tree 看成维护一个集合：

```text
S
```

然后只有两个操作：

```cpp
add(x);
remove(x);
```

并且要支持：

```cpp
query(S)
```

那么：

```text
dfs(u)
```

做的事情其实就是：

```text
先把 S 调整为 subtree(u)
然后 query(S)
```

---

# 30. 一个更加直观的过程

假设：

```text
             1
          /  |  \
         2   3   4
        / \
       5   6
```

假设：

```text
2 是重儿子
3、4 是轻儿子
```

处理节点 1：

### 处理 3

```text
S = subtree(3)
```

然后：

```text
clear
```

得到：

```text
S = ∅
```

### 处理 4

```text
S = subtree(4)
```

然后：

```text
clear
```

得到：

```text
S = ∅
```

### 处理 2

```text
S = subtree(2)
```

因为：

```text
keep=true
```

所以：

```text
S 保留下来
```

### 加入 subtree(3)

```text
S = subtree(2) ∪ subtree(3)
```

### 加入 subtree(4)

```text
S = subtree(2) ∪ subtree(3) ∪ subtree(4)
```

### 加入 1

```text
S = subtree(1)
```

于是：

```cpp
ans[1] = query(S);
```

---

# 31. 你可以把整个过程理解成“垃圾回收”

这个类比很有帮助。

假设有：

```text
大容器 = 重儿子
小容器 = 轻儿子
```

我们始终：

```text
保留大容器
丢掉小容器
需要时再把小容器中的元素倒进去
```

而不是：

```text
每次都把整个容器倒空重新建
```

这正是为什么复杂度下降。

---

# 32. 为什么一定是“最大的儿子”作为重儿子？

因为我们希望：

```text
保留下来的部分尽量大
重新加入的部分尽量小
```

假设：

```text
子树大小：

100
10
5
```

当然应该：

```text
保留 100
重新加入 10 + 5
```

而不是：

```text
保留 10
重新加入 100 + 5
```

所以自然选择：

```text
最大子树
```

---

# 33. 和树链剖分中的“重儿子”有什么关系？

这两个“重儿子”其实来源完全一致。

树链剖分中：

> 重儿子 = 子树最大的儿子

DSU on Tree 中：

> 重儿子 = 子树最大的儿子

都是利用：

[
size[heavy]\ge size[light]
]

从而产生“轻边至少缩小一半”的性质。

所以：

> **树链剖分和 DSU on Tree 在“重轻划分”的数学基础上是相似的。**

---

# 34. 但是 DSU on Tree 并不等于树链剖分

这一点一定要分清。

### 树链剖分

主要用于：

```text
路径查询
路径修改
```

例如：

```text
query(u,v)
update(u,v)
```

---

### DSU on Tree

主要用于：

```text
子树统计
```

例如：

```text
query(subtree(u))
```

所以：

```text
路径问题 → 树剖
子树颜色统计 → DSU on Tree
```

是非常典型的判断。

---

# 35. 为什么 DSU on Tree 通常是离线算法？

因为：

> 所有树结构和查询通常都是提前知道的。

它会先计算：

```text
size
heavy son
dfs order
```

然后统一 DFS。

所以它不太适合：

```text
动态加边
动态删边
在线改变树结构
```

---

# 36. 什么时候应该想到 DSU on Tree？

看到以下关键词时，应该立刻想到：

> **对于每个节点的子树，统计颜色 / 数值 / 出现次数 / 最大频率**

例如：

```text
每个节点有一个颜色 c[u]

求每个 u：
子树中出现次数最多的颜色
```

或者：

```text
每个 u：
求 subtree(u) 中不同颜色个数
```

或者：

```text
每个 u：
求 subtree(u) 中出现次数恰好为 k 的颜色数
```

这类题基本都是 DSU on Tree 的典型应用。

---

# 37. 判断是否能用 DSU on Tree 的三个条件

我建议你以后看到题目，可以检查：

### 条件一

询问对象是不是：

```text
某个节点的整个子树
```

如果是，很适合。

### 条件二

是否可以维护：

```text
add(x)
remove(x)
```

如果可以，很适合。

### 条件三

答案能否从当前集合快速计算？

例如：

```text
不同颜色数
最大频率
频率统计
总和
```

如果可以，DSU on Tree 很可能就是正解。

---

# 38. DSU on Tree 最容易犯的几个错误

## 错误 1：重儿子判断错

必须：

```cpp
if (sz[v] > sz[son[u]])
    son[u] = v;
```

而不是按：

```text
节点编号
```

之类的东西。

---

## 错误 2：忘记跳过父节点

```cpp
if (v == fa) continue;
```

否则无限递归。

---

## 错误 3：把轻儿子也设成 keep=true

错误：

```cpp
dfs(v, u, true);
```

通常应该：

```cpp
dfs(v, u, false);
```

---

## 错误 4：忘记清空

```cpp
if (!keep)
    clear...
```

如果不清，状态会污染后面的计算。

---

## 错误 5：加入自己的顺序不对

必须保证最终：

```text
重子树
+
轻子树
+
自己
=
整个子树
```

---

# 39. 一个非常重要的理解方式

不要死记：

```cpp
dfs(v, u, false);
dfs(son[u], u, true);
```

而应该记住：

> **谁最大，就留下谁；谁小，就算完扔掉；最后把小的重新倒进大的。**

这句话实际上就包含了整个 DSU on Tree。

---

# 40. 最终把 DSU on Tree 总结成一张图

整体过程：

```text
              u
          /   |   \
       light light heavy
         ↓      ↓    ↓
       计算    计算   计算
         ↓      ↓    ↓
       清空    清空   保留
                       ↓
                       S
                       ↓
            加入所有 light
                       ↓
                    加入 u
                       ↓
                   subtree(u)
                       ↓
                      ans
                       ↓
               根据 keep 决定
                   是否清空
```

而复杂度的本质：

```text
重子树：保留
轻子树：反复搬运
```

轻边每经过一次：

[
size\rightarrow \le \frac{size}{2}
]

所以：

[
\boxed{O(n\log n)}
]

---

# 41. 你现在最应该掌握的 DSU on Tree 模板

最终可以浓缩成：

```cpp
dfs1(u):
    求 sz[u]
    求 son[u]

dfs2(u, keep):

    处理所有轻儿子，keep=false

    处理重儿子，keep=true

    加入所有轻儿子的整棵子树

    加入 u

    计算 ans[u]

    如果 keep=false
        清除整棵 subtree(u)
```

也就是：

```cpp
for (light)
    dfs(light, false);

dfs(heavy, true);

for (light)
    addSubtree(light);

add(u);

ans[u] = query();

if (!keep)
    clearSubtree(u);
```

只要你把这一段真正理解透，DSU on Tree 基本就入门了。
