# 二维坐标编码为一维整数的原理详解

将二维坐标 `(x, y)` 编码为一维整数 `(x-1)*m + (y-1)` 是一种常见的技巧，用于在二维网格中进行线性存储和索引。下面详细解释这个编码公式的原理：

## 基本思想

在二维网格中，每个单元格可以用行和列两个维度表示。编码的目的是将这两个维度的信息合并为一个唯一的整数，使得：
1. 每个二维坐标对应唯一的一维索引
2. 编码和解码是可逆的
3. 索引是连续的，便于存储和访问

## 编码公式解析

### 公式：`id = (x-1) * m + (y-1)`

- **`(x-1)`**：将行号从1-based转换为0-based。如果行号从1开始，减去1使其从0开始。
- **`* m`**：乘以列数 `m`，表示跳过前面的 `(x-1)` 整行。每一行有 `m` 个单元格，所以要到达第 `x` 行，需要跳过 `(x-1)` 行，每行 `m` 个单元格。
- **`+ (y-1)`**：加上列偏移量。同样，将列号从1-based转换为0-based，表示在当前行中的位置。

### 举例说明

假设有一个3×4的网格（n=3, m=4）：

| 坐标(x,y) | 编码计算 | 编码结果 |
|-----------|----------|----------|
| (1,1)     | (1-1)×4 + (1-1) = 0×4 + 0 | 0 |
| (1,2)     | (1-1)×4 + (2-1) = 0×4 + 1 | 1 |
| (1,3)     | (1-1)×4 + (3-1) = 0×4 + 2 | 2 |
| (1,4)     | (1-1)×4 + (4-1) = 0×4 + 3 | 3 |
| (2,1)     | (2-1)×4 + (1-1) = 1×4 + 0 | 4 |
| (2,2)     | (2-1)×4 + (2-1) = 1×4 + 1 | 5 |
| (2,3)     | (2-1)×4 + (3-1) = 1×4 + 2 | 6 |
| (2,4)     | (2-1)×4 + (4-1) = 1×4 + 3 | 7 |
| (3,1)     | (3-1)×4 + (1-1) = 2×4 + 0 | 8 |
| (3,2)     | (3-1)×4 + (2-1) = 2×4 + 1 | 9 |
| (3,3)     | (3-1)×4 + (3-1) = 2×4 + 2 | 10 |
| (3,4)     | (3-1)×4 + (4-1) = 2×4 + 3 | 11 |

可以看到，每个坐标都得到了一个唯一的索引，从0到11（总共12个单元格，对应3×4=12）。

## 解码公式解析

### 公式：`x = id / m + 1`, `y = id % m + 1`

- **`id / m`**：整数除法，得到行偏移量（0-based）
- **`+ 1`**：将行号从0-based转换回1-based
- **`id % m`**：取模运算，得到列偏移量（0-based）
- **`+ 1`**：将列号从0-based转换回1-based

### 解码示例

继续使用上面的例子：

| 编码id | 解码计算 | 解码结果 |
|--------|----------|----------|
| 0      | x=0/4+1=1, y=0%4+1=1 | (1,1) |
| 5      | x=5/4+1=1+1=2, y=5%4+1=1+1=2 | (2,2) |
| 10     | x=10/4+1=2+1=3, y=10%4+1=2+1=3 | (3,3) |

## 在算法中的应用优势

1. **存储效率**：可以使用一维数组（如 `vector<int> dist(n*m)`）代替二维数组，减少内存开销和访问时间。

2. **队列操作**：在BFS中，队列只需要存储整数而非坐标对，提高效率。

3. **前驱记录**：使用一维数组 `par` 记录每个单元格的前驱，简化路径重建。

4. **哈希和集合操作**：使用整数作为键比使用坐标对更高效。

## 变体

有时也会使用 `(x-1)*m + y` 的编码方式，这种情况下解码为：
- `x = (id-1) / m + 1`
- `y = (id-1) % m + 1`

但原代码中使用 `(x-1)*m + (y-1)` 更为常见，因为它直接产生0-based的索引，与数组索引习惯一致。

这种编码方式在网格类问题中非常实用，是算法竞赛和编程中的常用技巧。
